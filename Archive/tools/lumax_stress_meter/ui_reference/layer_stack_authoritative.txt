Lumax stress meter — authoritative compositing model (user-defined)
====================================================================

Two ways to read the stack
----------------------------
• **Front → back** (what you “see” first): numbered **①–⑤** below — useful when authoring and
  when explaining why mist must sit above chrome.

• **Back → front** (implementation draw order): draw **⑤ first**, then **④**, …, **① last**.
  That matches how painters / canvas / PIL composites usually work.


Front-to-back list (① = uppermost)
------------------------------------
① **Mist / light effects** — **Seven individual** mist quads (one per lamp), fully transparent
   between cells. Each can animate **independently** (phase, drift, glimmer, optional slow “spin”).
   **Uppermost** so bezel glass and frame reflex do not tint or overpower the shimmer. Variants:
   dark theme vs light theme (different mist gain / hue).

② **Frames (chrome)** — One asset per **form** variant: outer frame, inner glass reflex, shadows;
   **transparent background** and transparent holes over the seven lamps. Not a continuous fill
   across the holes — the lit area stays open so ③–⑤ show through.

③ **Mask** — One asset per **form** variant: defines the **exact hole shapes** matching the frame
   openings (clip / alpha matte). Composites with ④+⑤ so only the seven cells receive color + dim.
   (If the frame PNG is authored with perfectly matching cut-outs, mask + frame must still align;
   often mask is the source of truth for hit-testing and clip.)

④ **Dimmers** — Seven **non-transparent** (or near-opaque) square images in a row — per-lamp
   brightness / “off” state. **Per-channel** control: seven independent opacity or seven tiles.
   Variants: dark theme vs light theme. Sits **above** the colored lights so dimming modulates how
   much hue reads through.

⑤ **Colored lights** — **Seven individual squares** (implementation), one per channel. Each cell
   carries its own stress hue (cool → hot mapping) and can animate **per lamp** (diagonal glass
   gradient, highlight drift). For a stronger **glass** read, each square may use a **diagonal
   intensity gradient** (e.g. upper-left brighter → lower-right softer). Assets may still be one
   **atlas** image or seven draw calls — logical model is **seven quads**, not one undivided fill.


One piece vs seven pieces (multiply-friendly layers)
----------------------------------------------------
• **Must be seven individual squares** (per-channel control): **① mist** and **⑤ colored lights**
  — animation, hue, and diagonal glass differ per lamp.

• **May be one asset / one rect** where nothing needs to vary per lamp: **② frames** and **③ mask**
  are naturally **one piece per form**; composite or **multiply** them over the lit stack as a
  single layer.

• **④ Dimmers** — Either **seven** tiles (independent dim per channel) **or**, if acceptable for a
  given theme, **one** multiply strip / texture over all seven cells when dimming is uniform; the
  seven-slot layout still matches the same grid as **①** and **⑤**.


Seven-cell layout (responsive row)
-----------------------------------
• **Preferred behaviour**: place the seven lamp quads in a row that is **horizontally centered** in
  the meter content area; each cell uses **100% height** of the lamp band (full vertical extent of
  the lit row). Cell **widths** stay **proportional** to that row (see below). On **resize**,
  **custom taskbar height**, or **DPI** changes, the row **re-centres** and **re-scales** — **micro
  gaps** and lamp size track automatically without hard-coded pixel gutters.

• **Proportions** (of the **lamp row** inner width): each cell **14%** wide → **7 × 14% = 98%**;
  the remaining **~2%** is **micro spacing** across six gutters (≈ **0.33%** of row width each if
  equal). Percentages apply to **whatever** the row width is after layout.

• **Authoring / implementation options** (equivalent when math matches):
  - **Centered flex or grid** — Inner row width defines the basis; **justify-content: center** (or
    equivalent); cells **14%** of that row (or `gap` from the 2% budget). Height **100%** of the bar’s
    lit band.
  - **Single atlas / one rect** — Strip with transparent gutters between seven quads; positions from
    the **same** centered, proportional row so assets match runtime.

• All layers that align to the lamps (**① ④ ⑤** and mask holes in **③**) should share this **same**
  grid so hit-testing and animation line up.


Notes
-----
• Data channels (behaviour): CPU, GPU, RAM, VRAM, DISK, SWAP, NET — see ux_behavior_spec.txt.

• **Form variants** (e.g. seven default designs): swap **② + ③** together (frame + matching mask
  geometry). **①** mist and **⑤** colors follow the same seven-cell grid; **④** matches that grid.

• **Theme**: **⑤** color strip + **①** mist + **④** dimmer art can follow dark vs light packs;
  **②** may need separate chrome reads for light vs dark backgrounds (see visual_spec_wow_supplement.txt).

• **Tk / PIL**: composite ⑤→④ with mask ③, then ②, then **①** last; or render ⑤+④ into an
  offscreen buffer, apply ③, then paste ② and ①. Animations update **①** (and optionally **④** or
  **⑤** diagonal gradient / highlight) on a timer.


Legacy (superseded wording)
---------------------------
Earlier notes described one continuous gradient under seven dim layers; the product direction is now
**seven discrete colored cells** (each may use a **per-cell diagonal glass gradient**) plus **seven
dimmer cells** + **mist on top**, as above.
