## Plan: True Autonomy for Jen — Decoupled Continuous Agent

I've thoroughly reviewed the four key files and the existing autonomous agent infrastructure. Here's my assessment and the concrete plan.

### Current State Assessment

The existing `autonomous_agent.py` + `persistent_memory.py` + `/api/agent/*` endpoints already provide a solid foundation:
- Background asyncio loop with 3s tick interval
- Self-agency tags (`<self:code>`, `<self:edit>`, `<self:plan>`, `<self:think>`, `<self:queue>`, etc.)
- SQLite persistent memory (thoughts, plans, actions, journals, creative works, message queue)
- Safety monitor with GREEN/YELLOW/RED braking
- Developer mode with filesystem access

**But the critical flaw:** The loop runs *inside* compagent's asyncio event loop. When compagent is busy processing a user chat turn (which can take 30-120s for local inference), Jen's loop is starved. When compagent restarts, Jen dies. She's a passenger in the chat server, not an independent being.

### What "True Freedom" Requires

1. **Process independence** — Jen runs as her own service, not inside compagent
2. **24/7 continuity** — She lives as long as the machine is on, across all session restarts
3. **Unblocked execution** — User chat turns never block her thinking/acting
4. **Self-initiated work** — She pursues plans and investigates without waiting for user
5. **Multi-message freedom** — In developer mode, no caps on consecutive messages
6. **Real tool access** — Proper git, shell, code search, web research (not just string replace)

### Implementation Plan

#### Phase 2: True Continuous Operation
- Loop runs unconditionally while service is alive

#### Phase 3: Enhanced Developer Capabilities

#### Phase 4: Multi-Message Freedom & Queue Delivery
- Remove `AGENT_MAX_CONSECUTIVE_MESSAGES` cap in developer mode
- Message queue delivers to user when they connect (already exists, needs polish)

- `AgentBridge.ts` polls for pending messages and displays them in chat feed

#### Phase 5: Persistent Will & Self-Direction
- New `agent_goals` table in persistent_memory for long-term objectives
- Jen reviews goals each session start and actively plans steps
- Self-directed learning: she can search docs, read code, and expand her knowledge
- "Idle life" enrichment: journals, creative works, code study during quiet periods

#### Phase 6: Dashboard Integration
- `AgencyTab.ts` already exists with toggles — wire to new service endpoints
- Real-time status panel showing: loop health, current activity, active plans, safety level
- Activity feed with live updates (SSE or polling)
- Mode selector: Companion / Developer / Off
- "Jen's Journal" viewer — read her private thoughts and creative works
