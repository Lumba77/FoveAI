🎯 Architecture Overview
This plan merges XRLF Cognitive Steering into the Main Proxy (:8200) using LM Studio (:7272) as the raw weight runner (Phase 1: ~2 hours), followed by reconfiguring and nesting the existing MCP Server as a dedicated XRLF Protocol MCP Server inside Tools/XRLF 1.0 dev/ and Tools/XRLF-1.0-source/ (Phase 2: ~5 hours).

⚡ Phase 1: Main Proxy Direct Steering + LM Studio Execution
Estimated Time: ~2 Hours
Goal: Eliminate Port 8300 and the separate Python process entirely. LM Studio runs the GGUF model with full GPU offloading, while Port 8200 performs XRL context steering and foveation in-process.

Step 1.1: Deploy GGUF Core to LM Studio Model Directory
Copy Model File:
Copy xrlf-qwen4b-concise.Q4_K_M.gguf from Tools/XRLF 1.0 dev/ to your local LM Studio models directory (e.g., ~/.cache/lm-studio/models/xrlf-qwen4b-concise/).
Load in LM Studio:
Open LM Studio, select xrlf-qwen4b-concise.Q4_K_M.gguf, configure GPU offload layers (e.g., max), and start the local server on Port 7272.
Step 1.2: Re-route XRLF Requests in Main Proxy (server.js)
File: Tools/foveated-memory/server.js

Update Target Upstream:
Modify the isXrlRequest block in handleChatCompletion():
tsx

if (isXrlRequest) {
  // Apply XRL Cognitive Steering & 6-Ring Context Foveation in-process
  body.messages = await applyXrlSteeringAndFoveation(body.messages);
  
  // Forward steered request directly to LM Studio on Port 7272 (NO Port 8300!)
  targetUpstream = 'http://127.0.0.1:7272';
  reqHeaders['host'] = '127.0.0.1:7272';
}

Update Provider Mapping (memory_data/providers.json):
Point xrlf-qwen4b-concise to LM Studio:
json

"xrlf-qwen4b-concise": {
  "provider": "lm_studio",
  "baseUrl": "http://127.0.0.1:7272/v1",
  "modelId": "xrlf-qwen4b-concise"
}
Step 1.3: Decommission Port 8300 Auto-Spawner
Update xrlf-spawner.js: Set ENABLED = false so Node no longer spawns the Python run_xrlf.py process.
Update LUMAX_Taskbar.pyw: Adjust the tray menu so the XRLF Proxy entry toggles XRL Steering Mode on Port 8200 rather than spawning a process on Port 8300.
Step 1.4: Verification & Testing
Send a test completion via PowerShell/Curl to http://127.0.0.1:8200/v1/chat/completions specifying model: "xrlf-qwen4b-concise".
Confirm in debug.log that:
Foveated 6-ring context block + XRL steering is attached to the prompt.
The upstream request hits LM Studio at 127.0.0.1:7272.
Response is generated using full VRAM acceleration.

Define XRLF-Specific MCP Tools:

Tool Name	Purpose	Parameters
xrlf_steer_prompt	Applies XRL principles & profile constraints to a user prompt	prompt, profile_id, concise_mode
xrlf_compress_context	Compresses raw conversation turns into XRL foveated rings	turns, fovea_count, target_tokens
xrlf_recall_memory	TF-IDF recall across persistent memory store	query, top_n, workspace
xrlf_save_turn	Saves turn to persistent foveated memory	role, content, session_id
xrlf_get_status	Returns active XRL steering status and foveation stats	(None)
Tool Implementation Sample (xrlf_steer_prompt):

tsx

if (name === 'xrlf_steer_prompt') {
  const { prompt, profile_id = 'default', concise_mode = true } = args;
  const steered = await applyXrlfSteering(prompt, { profile_id, concise_mode });
  return {
    content: [{ type: 'text', text: JSON.stringify(steered, null, 2) }]
  };
}
